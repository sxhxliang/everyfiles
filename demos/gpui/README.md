# everyfiles gpui demo

用 [gpui](https://gpui.rs)（Zed 的 GPU 加速 UI 框架）给 everyfiles 引擎套一个最小的窗口：输入即搜索，`⌘P` 切换拼音匹配，文件系统的变动自动进入索引。

```sh
cd demos/gpui
cargo run --release -- ~/Documents     # 省略参数则索引当前目录
```

第一次打开会扫描并保存索引；索引文件和 `everyfiles` 命令行工具用的是同一个缓存位置，所以之后再打开（或者命令行先 `everyfiles index` 过）就是零拷贝加载，不到一毫秒。

界面：

- 顶部：根目录、拼音开关（默认开）。
- 搜索框：支持中文输入法、粘贴、光标移动与选区；每次编辑都重新查询。输入法组词期间（例如拼音输入法显示 `pin'yin`）会去掉音节分隔符去查，所以还没上屏就已经在按拼音找了；上屏成汉字后按汉字字面匹配。
- 状态行：命中数、匹配耗时、索引规模、索引来源；查询不合法时（例如拼音模式下用了 `*`）显示引擎返回的错误。
- 监听行：当前监听器（macOS 是 FSEvents）和最近一批变更的 +新增 -删除 ~更新。
- 结果：按名字排序的前 300 条，目录名黄色，右侧是所在目录。引擎用 `select_nth` 取前 300，再多的命中也不会全排序。
- 底部右侧：重新索引按钮（`⌘R`），工作时图标旋转。

**变动自动生效。** 窗口打开后，后端的监听器在自己的线程上运行，和 `everyfiles watch` 是同一套 `Updater`：每批事件按路径与文件系统对账，发布一份快照，窗口拿到快照就重跑当前查询。新建、删除、重命名一个文件或文件夹，大约一秒内（FSEvents 延迟加 150 ms 合并窗口）就能搜到。索引每 10 秒连同续传令牌一起落盘，下次启动直接回放中间错过的事件。

**`⌘R` 是补扫而不是全量重扫。** 有监听器时，它让监听线程做一次目录 mtime 扫描：只重新列出 mtime 变过的目录，这正是索引过期时需要的，也是引擎在事件队列溢出后自己做的事，比重扫整棵树便宜得多。监听器启动失败时（状态会写明），`⌘R` 退回到后台线程全量重扫。

试试：`pysousuo` → 拼音搜索，`cq` → 重庆，`拼音sousuo` 混排，`report` 走和命令行一样的子串快路径。

按键：`⌘P` 切换拼音 · `⌘R` 重新索引 · `esc` 清空 · `⌘A/⌘C/⌘V/⌘X` · `⌘Q` 退出。

调试：`EVERYFILES_DEMO_TRACE=1` 会把每次查询、每批变更和补扫打到 stderr。

这个 crate 有自己的 `[workspace]`，**不是**仓库 workspace 的成员：gpui 的依赖树很大，Linux 上还需要显示服务器，不该进入引擎的 `cargo test --workspace`、`xcheck` 和 CI。它只通过门面 crate `everyfiles`（开启 `pinyin` 特性）使用引擎。搜索框改自 gpui 自带的 `input` 示例，另外把输入法发来的范围裁剪到当前文本内：这些回调来自 Objective-C，越界切片的 panic 会直接 abort。
